## alerting-webhook

### databay alerting-webhook create

Create a webhook for the active project (``scope: project``, the default) or the organization.

``scope: organization`` receives alerts from every project and needs an org admin (403
``webhook_forbidden``).

Acts in a project, sent as the X-Databay-Project-ID header: --project, else the profile's active project.

```
Examples:
  databay alerting-webhook create --type discord --name <name> --url-env <url_env>
```

Usage: `databay alerting-webhook create [OPTIONS]`

| Argument or flag | Required | Description |
|---|---|---|

| `--scope STRING` |  | project: alerts from the active project only (a create's default); organization: alerts from every project (org admins only). Omitted on update: unchanged. One of: project, organization. |
| `--tags LIST` (repeat) |  | alerting webhook tags |
| `--type STRING` | yes | alerting webhook type. One of: discord, telegram. |

### databay backfill-run create

Re-read the pipe's table.

A streaming pipe is resynced: its table is copied again from a new snapshot (the rebuild
route's ``snapshot`` source), and ``Idempotency-Key``, when sent, is that rebuild's key: repeating
it returns that rebuild, whatever the body says. Any other pipe ignores the key.

Removes or overwrites state: asks on a terminal, and needs --yes when output is captured.

Answers at once: `next` names the command that waits for it.

```
Examples:
  databay backfill-run create --pipe-uuid <pipe_uuid> --yes
```

Usage: `databay backfill-run create [OPTIONS]`

| Argument or flag | Required | Description |
|---|---|---|
| `--cursor-field STRING` |  | Optional cursor column to scope the backfill (e.g. 'updated_at'); the sync resumes from the given cursor. Not every engine supports it. |
| `--pipe-uuid STRING` | yes | UUID of the v2 pipe to sync |
| `--snapshot-type STRING` |  | How the re-read is performed on a streaming pipe. `incremental` walks the table by primary key while replication keeps running, reconciling against the live stream. `blocking` pauses replication, re-reads the table in one pass, then resumes from the paused offset — faster and point-in-time consistent, at the cost of replication lag for the duration. `where_clause` means the same thing in both modes. Requesting `blocking` on a backend that cannot pause its own stream is a 422 rather than a signal that would be silently dropped. One of: incremental, blocking. |
| `--start-date STRING` |  | Re-read history from this ISO date (YYYY-MM-DD). Only pipes whose engine re-runs a source from a date accept it (scheduled SaaS pipes); anywhere else it is a 422, never a silently ignored window. Clamped server-side to the source's backfill ceiling (see GET /api/cdc/backfill/limits); omit it for 'as far back as this source allows'. The response says what actually ran. |
| `--where-clause STRING` |  | Row filter scoping the backfill, e.g. "status = 'pending' AND amount > 100". Accepted only where the pipe's engine supports a filtered backfill (`supports_filtered_backfill` in GET /api/cdc/pipe/config-options); elsewhere it is a 422. NOT arbitrary SQL: the expression is parsed against a restricted grammar — columns this pipe replicates, comparison and boolean operators, IS NULL, IN, BETWEEN, and literals — and rebuilt from the parse tree before use. Function calls, subqueries, casts and comments are rejected with 422. A full `SELECT ... FROM ... WHERE ...` is therefore invalid in either snapshot mode: pass only the condition that would follow WHERE. |
| `--file TEXT` |  | read the whole body as JSON from a file, or - for stdin |

### databay source delete

Delete a source that nothing depends on; never cascades.

(403 ``not_home`` for a shared source). 204 when the source is unused, 409 (with the

## Hand-written commands

`databay <command> --help` lists the flags of each.

| Command | What it does |
|---|---|
| `databay login` | Sign in and save a profile |
| `databay logout` | Sign out: revoke and delete the profile's credential |
| `databay pipe wait` | Wait until a pipe is active or its table is ready to query |
| `databay profile` | Switch between and list profiles |
| `databay project use` | Set the profile's active project |
| `databay skill` | Install the agent skill for Claude Code or Codex |
| `databay sql` | Run one read-only SQL statement |
| `databay status` | Who and where: profile, server, user, org, project, skill |
